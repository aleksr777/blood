# Тансфузия

Веб-приложение для заполнения, сохранения и печати бланков трансфузиологии:
протокола трансфузии, листа регистрации трансфузий, направления на индивидуальный
подбор и заявки в трансфузиологический кабинет.

В приложении есть база реципиентов, общие данные для текущих бланков и архив
с отдельными режимами просмотра и редактирования сохранённых документов.
Медицинские данные хранятся локально в браузере пользователя. После более 24 часов
бездействия рабочие бланки очищаются и снимается выбор текущего реципиента;
цоликлоны и сохранённые документы остаются.

## Запуск

Для разработки необходим Node.js 22.12+ (ветка 22), 24 или 26+.

```bash
npm ci
npm run dev
```

## Проверка и сборка

```bash
npm run check
npm run preview
```

`check` запускает ESLint, регрессионные тесты, проверку TypeScript и production-сборку.
Тесты хранилища используют настоящий SQLite WASM с временной базой в памяти.
Проверки автоматически выполняются для ветки `develop` и pull request в `develop`/`main`.

[Ограничения числового и текстового ввода](docs/input-limits.md) заданы общими компонентами полей.
[Результаты проверки проекта от 30.10.2026](docs/project-review.md) описывают исправления и выполненные проверки.

Данные текущего реципиента общие для всех текущих бланков. При смене реципиента
заполненные несохранённые бланки сохраняются для предыдущего реципиента.
Изменение карточки реципиента само по себе не переписывает архив. При сохранении
протокола запись с тем же номером гемакона у этого реципиента обновляется;
другой номер создаёт новую запись. Пробелы в номере не влияют на поиск совпадения.
Листы регистрации и заявки с изменённым содержимым сохраняются отдельными записями.

Для всех четырёх видов бланков действует общая проверка повторного сохранения
в базе. Если у этого же реципиента уже есть такой же бланк того же типа,
возвращается существующая запись без изменения её дат. Порядок полей, пустые
значения, служебные данные автозаполнения и пробелы по краям не создают дубль.
Снимки медицинских данных, порядок строк и ссылки на трансфузии учитываются.
Проверка и запись выполняются в одной транзакции для ручного сохранения
и автосохранения при смене реципиента. Печать сама по себе не сохраняет бланк:
после неё приложение предлагает сохранить изменения или продолжить без сохранения.

Сохранение и печать протокола доступны после заполнения наименования компонента,
номера гемакона из 14 цифр, группы крови AB0 гемакона, дат заготовки и окончания
срока годности, даты и времени подачи заявки, даты трансфузии и времени её начала
и окончания. Объём не обязателен для разблокировки кнопок. Предупреждение в панели появляется
при нажатии на сохранение или печать, в том числе на заблокированные кнопки.
Незавершённые данные остаются в текущем черновике. При печати через меню браузера
вместо незаполненного протокола выводится предупреждение.
После сохранения и возврата к текущему протоколу очищаются данные гемакона,
время переливания, наблюдение и ФИО персонала; дата и остальные разделы сохраняются.

В листе регистрации и в окне «Трансфузии для листа регистрации» компоненты
расположены по дате и времени начала трансфузии: от ранних к поздним.
Время последнего редактирования не влияет на порядок. Для старых протоколов без времени
начала используется время окончания; строки без времени идут в конце своего дня,
а без даты — в конце списка.

## Печать

Нажмите **«Печать A4»**. В диалоге браузера рекомендуется использовать:

- бумагу A4;
- масштаб 100%;
- книжную ориентацию;
- отключенные колонтитулы браузера.

Печатная форма разделена на две страницы A4. При печати панель управления и служебная подсказка скрываются.

## Client database

Persistent shared application data is stored locally in SQLite WASM using the OPFS
SyncAccessHandle Pool VFS (`opfs-sahpool`). SQLite runs inside a Web Worker and does not
require a backend or COOP/COEP response headers.

The storage is persistent between sessions for the same site origin and browser profile.
The SAH pool allows one active database connection per origin. Before mounting any forms,
the application checks database ownership. Additional tabs show a blocking dialog without
modifying drafts. This warning contains no buttons and cannot be dismissed; it remains
visible until the duplicate tab is closed.

Startup allows up to 60 seconds for downloading and opening SQLite and displays its current
stage. A failed startup stops its worker; retrying creates a fresh worker and reopens the
same storage. The optional persistent-storage permission request does not delay startup.
