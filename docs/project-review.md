# Проверка проекта — 30.10.2026

Проверены все четыре бланка, SQLite-хранилище и миграции, синхронизация текущего
реципиента, архивные режимы, печать, модальные окна, общие поля, стили, иконки
и конфигурация сборки. Изменения предназначены для ветки `develop`.

## Исправления

| Проблема | Исправление |
| --- | --- |
| При смене реципиента заявка или направление с одними показаниями к трансфузии могли очищаться без сохранения в архив. | Используется общий критерий заполненности бланка, включая вложенные показания и выбор группы компонентов. Одни перенесённые данные ЛПУ и персонала, данные реципиента и группа «Эритроциты» по умолчанию в направлении не создают пустые архивные записи. |
| Ошибка SQLite при удалении реципиента могла оставить его карточку, уже удалив связанные документы. | Удаление карточки и всех четырёх групп бланков выполняется одной транзакцией. При ошибке все удаления откатываются. |
| Защита модальных окон от прокрутки фона могла перехватывать пробел и отменять нажатия кнопок с клавиатуры. | Пробел сохраняет стандартное действие интерактивных элементов; события, уже обработанные контролом, не вызывают дополнительную прокрутку. |
| Отсутствующий объём гемакона превращался в `0` литров в листе регистрации. | Пустое значение остаётся пустым. Указанный объём переводится из миллилитров в литры, включая дробные значения с запятой. |

## Рефакторинг

- Заявка и направление используют общий механизм восстановления данных из черновика
  и архива. Сохраняется фильтрация полей и типов, исторические строки не обрезаются,
  вложенные словари копируются отдельно от архивного снимка.
- Удалены две неиспользуемые функции прежней фильтрации и сортировки трансфузий,
  связанный парсер даты и неиспользуемый CSS-селектор.
- Убраны лишние экспорты вспомогательных функций, констант и типов.
- Справочники групп крови и резуса вынесены из React-компонента; устранены пять
  предупреждений, мешавших корректному горячему обновлению этого модуля в разработке.
- Уточнено описание сохранения после печати в README.

## Проверка в браузере

Сценарии выполняются в Chromium с отдельным тестовым профилем и вымышленными
реципиентами. Проверяются четыре страницы, блокировка действий для пустого бланка,
смена реципиента, сохранение показаний, модальные окна и ввод чисел, работа пробела,
вторая вкладка, печать без автоматического сохранения, режимы просмотра и
редактирования, обновление исходной архивной записи, возврат к списку и очистка
рабочих полей. Проверяется ширина страницы и окна реципиентов при экране 390 px.
Диалог системной печати заменяется событием `afterprint`; физическая печать
на принтере в эту проверку не входит.

Готовая сборка дополнительно открывается с обычного статического сервера без
COOP/COEP-заголовков: проверяется запуск SQLite и переходы между четырьмя страницами.
